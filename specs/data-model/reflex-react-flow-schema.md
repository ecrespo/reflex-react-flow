There is no database. The "data model" is the set of serializable structures that
cross the Python↔browser boundary, specified with database-schema rigor: types,
required fields, defaults, validation, and the JSON `node.data` schema per registry
node type. These schemas are public API (breaking change ⇒ major version).

---

## 1. Model Overview

```
┌───────────┐  1:N   ┌──────────┐          ┌────────────┐
│ FlowState │───────▶│   Node   │◀──N:1────│   Node     │  (parent_id — subflows)
│           │  1:N   ├──────────┤  parent  └────────────┘
│           │───────▶│   Edge   │──source/target (N:1 by id)──▶ Node
└───────────┘        └──────────┘
      ▲                    ▲
      │ applies            │ references by id
┌─────┴──────┐      ┌──────┴──────┐
│ NodeChange │      │ EdgeChange  │   + Connection, Viewport
└────────────┘      └─────────────┘
```

Access patterns: full `nodes`/`edges` lists serialized as props on every state
change (Reflex delta-compresses); change payloads flow browser→Python per event.
Integrity (edge endpoints exist, parent exists) is enforced at the application level
— there is no referential enforcement in the browser.

## 2. Entities

### 2.1 `Node`

**Purpose:** One canvas node. Python dataclass → JSON object for the `nodes` prop.

#### Schema (serialized JSON)

```json
{
  "id": "string (required, non-empty, unique within nodes)",
  "position": { "x": "number (required)", "y": "number (required)" },
  "type": "string (default: 'default'; registry constant or custom key)",
  "data": "object (default: {}; schema per type — §4)",
  "parentId": "string | absent (must reference an existing node id)",
  "extent": "'parent' | [[number,number],[number,number]] | absent",
  "width": "number | absent (> 0)",
  "height": "number | absent (> 0)",
  "draggable": "boolean | absent (absent = inherit canvas default)",
  "selectable": "boolean | absent",
  "connectable": "boolean | absent",
  "hidden": "boolean (default: false)"
}
```

#### Field detail

| Python field | JSON key | Type | Required | Default | Validation (REQ-016) |
|---|---|---|---|---|---|
| `id` | `id` | str | Yes | — | non-empty; unique in `FlowState` |
| `position` | `position` | tuple/dict → `{x,y}` | Yes | — | both coords finite numbers |
| `type` | `type` | str | No | `"default"` | — (unknown type → REQ-023 fallback at render) |
| `data` | `data` | dict | No | `{}` | JSON-serializable; §4 per type |
| `parent_id` | `parentId` | str | No | absent | if set: must exist in nodes (checked by `FlowState.add_node`) |
| `extent` | `extent` | `"parent"` \| bounds | No | absent | `"parent"` requires `parent_id` set |
| `width`/`height` | `width`/`height` | float | No | absent | > 0 |
| `draggable`/`selectable`/`connectable` | camelCase | bool | No | absent | — |
| `hidden` | `hidden` | bool | No | `false` | — |

Subflow rule (REQ-015): the documented group container is `type="group_node"` (the
registry type — this is the path all docs, demos, and tests use). React Flow's built-in
`type="group"` is accepted as a **compatible alias** and renders the same subflow
behavior; this sentence is the single normative statement of that alias (A-03).
Children set `parent_id` + `extent="parent"`.
Parents MUST appear before their children in the `nodes` list (v12 ordering rule) —
`FlowState.add_node` maintains this invariant.

### 2.2 `Edge`

```json
{
  "id": "string (required, unique within edges)",
  "source": "string (required; node id)",
  "target": "string (required; node id)",
  "sourceHandle": "string | absent (HandleConfig id on source node)",
  "targetHandle": "string | absent",
  "type": "'bezier' | 'step' | 'smoothstep' | 'straight' (default: 'bezier')",
  "label": "string | absent",
  "animated": "boolean (default: false)",
  "markerStart": "EdgeMarker | absent",
  "markerEnd": "EdgeMarker | absent",
  "data": "object (default: {})"
}
```

| Python field | Required | Default | Validation |
|---|---|---|---|
| `id` | Yes (auto-generated by `FlowState.add_edge` when built from `Connection`: `e{source}-{target}[-{n}]`) | — | non-empty, unique |
| `source`, `target` | Yes | — | non-empty (existence checked at `FlowState` level, warning if missing) |
| `source_handle`, `target_handle` | No | absent | — |
| `type` | No | `"bezier"` | enum (REQ-017) |
| `label` | No | absent | rendered as text (XSS-safe) |
| `animated` | No | `false` | — |
| `marker_start`, `marker_end` | No | absent | §2.4 |
| `data` | No | `{}` | JSON-serializable |

### 2.3 `Viewport`

```json
{ "x": "number (default 0)", "y": "number (default 0)", "zoom": "number (default 1, min_zoom ≤ zoom ≤ max_zoom)" }
```

### 2.4 `EdgeMarker`

```json
{ "type": "'arrow' | 'arrowclosed' (required)", "width": "number (default 20)", "height": "number (default 20)", "color": "string | absent (CSS color)" }
```

### 2.5 `HandleConfig` (element of `node.data.handles`)

```json
{
  "id": "string (required, unique within the node's handles)",
  "type": "'source' | 'target' (required)",
  "position": "'top' | 'bottom' | 'left' | 'right' (required)"
}
```

Validation (REQ-021): duplicate handle `id` within one node → `ValueError` at model
construction. Edges referencing a `source_handle`/`target_handle` must match a
`HandleConfig.id` of type `source`/`target` respectively (checked with warning at
`FlowState.add_edge`).

## 3. Event payload structures (browser → Python)

### 3.1 `NodeChange` (REQ-005, REQ-031)

Discriminated union on `type`:

| `type` | Required fields | Optional | Semantics in `apply_node_changes` |
|---|---|---|---|
| `"position"` | `id`, `position:{x,y}` | `dragging: bool` | update node.position |
| `"dimensions"` | `id`, `dimensions:{width,height}` | — | update width/height |
| `"select"` | `id`, `selected: bool` | — | update selection sets |
| `"remove"` | `id` | — | remove node + incident edges |
| `"add"` | `item: Node` | — | append (maintaining parent-before-child order) |
| `"replace"` | `id`, `item: Node` | — | replace in place |

Constraint (REQ-005): for types position/dimensions/select/remove the payload MUST
NOT contain full node objects. `item` appears only for add/replace.

### 3.2 `EdgeChange` (REQ-006)

| `type` | Required fields | Semantics |
|---|---|---|
| `"select"` | `id`, `selected` | update selection |
| `"remove"` | `id` | remove edge |
| `"add"` / `"replace"` | `item: Edge` (+ `id` for replace) | append / replace |

### 3.3 `Connection` (REQ-007)

```json
{ "source": "string", "target": "string", "source_handle": "string|null", "target_handle": "string|null" }
```

### 3.4 Other event payloads (REQ-008–014)

| Event | Payload schema |
|---|---|
| `on_node_click` / `on_node_double_click` | `{id: str, type: str, position: {x,y}}` |
| `on_node_drag_start` / `on_node_drag_stop` | `{id: str, position: {x,y}}` |
| `on_edge_click` | `{id: str, type: str}` |
| `on_pane_click` | `{position: {x,y}}` (flow coordinates) |
| `on_selection_change` | `{node_ids: [str], edge_ids: [str]}` |
| `on_nodes_delete` / `on_edges_delete` | `[str]` (ids) |
| `on_viewport_change` | `Viewport` |
| `on_connect_start` | `{node_id: str, handle_id: str\|null, handle_type: "source"\|"target"}` |
| `on_connect_end` | `{connected: bool}` |

Global constraint (REQ-013): serialized payload ≤ `max_event_payload_kb` (default
32 KB); JS truncates change lists tail-first and warns.

## 4. Registry `node.data` schemas (Layer 2 — normative, REQ-020/021/024)

Common rules: all keys optional (defaults below, REQ-024); unknown keys ignored;
all strings rendered as text (never HTML); `handles` uses §2.5 `HandleConfig`.

### 4.1 `card_node`

**Icon set (normative, resolves A-02):** `icon` names an entry in the **bundled Lucide
subset** — a curated set of inline SVG path data copied from [Lucide](https://lucide.dev)
(**ISC License**, permitted by Constitution Art. 2 as amended A-2026-08-08-01) and
embedded directly in `assets/registry.jsx`. There is **no npm/runtime dependency** on
`lucide-react`; only the path data of the icons listed below travels in the wheel, with
the ISC notice reproduced in `assets/ICONS_LICENSE.md`.

Bundled names (v1): `activity`, `alert-triangle`, `bot`, `box`, `check`, `circle`,
`cpu`, `database`, `file-text`, `folder`, `git-branch`, `globe`, `layers`, `play`,
`server`, `settings`, `terminal`, `user`, `zap`. Unknown name → no icon rendered plus a
`[reflex-react-flow]` console warning (REQ-024 default path; never a crash). Adding an
icon to this list is an additive minor change (Data Model §7).

```json
{
  "icon":        "string (name from the bundled Lucide subset, see above) | default: none",
  "title":       "string | default: ''",
  "subtitle":    "string | default: ''",
  "badge":       "string | default: none (badge hidden)",
  "badge_color": "'gray'|'blue'|'green'|'yellow'|'red' | default: 'gray'",
  "handles":     "[HandleConfig] | default: [{id:'in',type:'target',position:'left'}, {id:'out',type:'source',position:'right'}]"
}
```

### 4.2 `agent_node`

```json
{
  "name":    "string | default: ''",
  "role":    "string | default: ''",
  "status":  "'idle'|'running'|'done'|'error' | default: 'idle'",
  "tokens":  "integer ≥ 0 | default: absent (counter hidden)",
  "calls":   "integer ≥ 0 | default: absent (counter hidden)",
  "handles": "[HandleConfig] | default: [{id:'in',type:'target',position:'top'}, {id:'out',type:'source',position:'bottom'}]"
}
```

Status → visual mapping (REQ-022): `idle` gray dot · `running` pulsing blue ·
`done` green check · `error` red. Invalid status value → treated as `idle` +
console warning.

### 4.3 `group_node`

```json
{ "title": "string | default: ''" }
```

No handles. Used with `parent_id`/`extent="parent"` children (§2.1 subflow rule).

### 4.4 `annotation_node`

```json
{ "text": "string (light markdown: **bold**, *italic*, `code`) | default: ''" }
```

Never renders handles; not connectable regardless of canvas defaults. Markdown is
whitelist-rendered (Tech Design §6) — no raw HTML.

### 4.5 `io_node`

```json
{
  "label": "string | default: ''",
  "kind":  "'input' | 'output' | default: 'input'"
}
```

`kind="input"` → exactly one `source` handle (right); `kind="output"` → exactly one
`target` handle (left). `handles` key ignored for this type (documented).

## 5. Invariants (application-enforced)

| ID | Invariant | Enforced by | On violation |
|---|---|---|---|
| INV-01 | `node.id` unique | `FlowState.add_node` | `ValueError` |
| INV-02 | `edge.id` unique | `FlowState.add_edge` | `ValueError` |
| INV-03 | Edge endpoints exist | `FlowState.add_edge` | warning naming the missing endpoint id **and stating that the edge will not be rendered by the canvas until that node exists**; the edge is still added to state (A-09) |
| INV-04 | Parent before child in `nodes` list | `FlowState.add_node` / `apply_node_changes` | reorder silently |
| INV-05 | `extent="parent"` ⇒ `parent_id` set | `Node.__post_init__` | `ValueError` |
| INV-06 | Handle ids unique per node | model validation | `ValueError` |
| INV-07 | Payload ≤ cap | JS event spec | truncate + warn (REQ-013) |

## 6. Serialization notes

- Python `snake_case` fields serialize to the camelCase JSON keys shown in §2 at the wrapper boundary only (Art. 4).
- All numbers are JSON numbers (positions may be float); no NaN/Infinity (validated, REQ-016).
- Round-trip guarantee: `Node.from_dict(node.to_dict()) == node` (tested).

## 7. Migration / compatibility

No stored data ⇒ no migrations. Schema evolution policy: additive optional keys =
minor version; renamed/removed keys or changed defaults = major + Delta Spec. The
`node.data` schemas of §4 follow the same policy (public API).
